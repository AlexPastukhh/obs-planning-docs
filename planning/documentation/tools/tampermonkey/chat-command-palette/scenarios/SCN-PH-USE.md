# SCN-PH-USE — Use Helper Content In ChatGPT

Status: active current behavior owner
Scope: canonical detailed application behavior owner; this Scenario owns its trigger/context/behavior/result/boundaries and traceability.

**Trigger/input:** the user chooses a command/helper/prompt row, favorites/unfavorites a Command or Use Case, or uses Full/refinement/Copy/Insert. A Planning Command may expose explicit one-shot invocation variants backed by Helper-owned side-effect code; ordinary delivery remains side-effect-free.

**Successful result:** without a registered side effect, the exact selected Command, Use-Case or Prompt RAM text is available on the clipboard and/or inserted into the current ChatGPT composer. With a registered command side effect, Helper first runs that asynchronous invocation code and appends only the body it returns after the complete unchanged canonical Command body for that invocation; semantic Use-Case bodies still focus the receiving chat on the selected UC, current registry entry and dynamically resolved current owner route; repository availability does not affect the normal insertion path; favorite state is local-only and does not change the inserted identity/body.

**Boundary:** Copy/Insert are delivery mechanisms of one user outcome, not separate Use Cases. A command-backed UC remains independently insertable from the Use Cases surface and does not redirect to/open the Commands surface. Planning-command insertion does not grant permissions beyond the command definition. Command side effects are Helper runtime behavior, not GitHub command semantic authority. For `replacement_archive.create`, ordinary Insert/Full/Copy does not bind; explicit `Bind + ...` creates one fresh invocation token, captures click-time chat context only in this tab's sessionStorage and appends the effect body. That explicit Bind is authority to bind or rebind the ChangeSet Review chat to the captured conversation when the consumer resolves the token. The token is required only in this invocation's OBS-ACTION and is not carry-forward state. A side-effect failure aborts only the requested bind delivery action.
