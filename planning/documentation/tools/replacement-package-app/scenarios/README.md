# Replacement Package App Scenario Catalog

Status: active Scenario navigation

Scenario identity follows a real application/user result rather than controls, commands or implementation components.

## Current owners

| Status | Scenario | Application result |
|---|---|---|
| CURRENT | [`SCN-RPKG-COMPLETE-REPOSITORY-WORK`](SCN-RPKG-COMPLETE-REPOSITORY-WORK.md) | Prepared/existing logical repository work is safely realized using current mixed legacy/Git-backed semantics and reaches the currently supported published/finalized or truthful recoverable boundary. |
| CURRENT + SELECTED EVOLUTION | [`SCN-RPKG-PROVIDE-REPOSITORY-CONTEXT`](SCN-RPKG-PROVIDE-REPOSITORY-CONTEXT.md) | One exact portable repository context is produced without changing repository work; selected evolution exposes one collision-resistant future Snapshot path to the clipboard before capture starts and removes in-application ChatGPT attachment/send from this Scenario. |

`Provide Current Change` is no longer a standalone Scenario owner. Current legacy ReviewDiff compatibility remains part of `SCN-RPKG-COMPLETE-REPOSITORY-WORK` while it exists. The selected target keeps only local `Copy Diff` support inside reviewed-package work when exact local work is known not to be published; it does not retain Current Change delivery to ChatGPT as Scenario behavior.

## Planned future owner

| Status | Scenario | Application result |
|---|---|---|
| PLANNED FUTURE | [`SCN-RPKG-COMPLETE-REVIEWED-REPOSITORY-WORK`](planned/SCN-RPKG-COMPLETE-REVIEWED-REPOSITORY-WORK.md) | One reviewed package follows one of three explicit routes: Apply Only stops applied/uncommitted; Apply And Publish stops pre-integration after exact reviewed-result confirmation; Apply And Finalize continues through integration, `## Final Work Record` and managed Issue closure. Local `Copy Diff` remains an optional pre-publish/manual support action, not a review or ChatGPT-delivery route. |

The planned reviewed-work Scenario is a selected target design, not a second current authority. It records Scenario-level realization dependencies but does not preassign future Domain/Slice/Shared ownership. Promotion requires downstream Requirements Discovery, implementation/proof reconciliation and evidence; the current Scenario remains authority until that happens.

Repository Snapshot path handoff intentionally stops at the clipboard/path boundary in the selected evolution. An independent external consumer may use the pre-announced exact path to wait for the artifact and later attach/send it elsewhere, but that external automation is outside Replacement Package App Scenario behavior.

Shared work-context selection, notifications and implementation capabilities support these Scenarios and are represented downstream rather than invented as extra user-world Scenarios.
