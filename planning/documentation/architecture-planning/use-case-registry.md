# Workspace Architecture Planning Use-Case Registry

Status: active reusable-family semantic registry
Parent Direction: [`direction-registry.md`](direction-registry.md)

| ID | Name | Status | Parent Direction | Purpose | Trigger / input | Result / end state | Boundaries | Main owner | Related command |
|---|---|---|---|---|---|---|---|---|---|
| `UC-PLAN-ARCH-STATE` | Understand / Review Workspace Architecture State | active proportional | `DIR-PLAN-ARCHITECTURE` | establish an inspectable current architecture baseline and identify material architecture/maintainability concerns relative to important Workspace work | current Workspace architecture needs orientation/review or an architecture baseline is needed before further work | current Architecture State + Architecture Intent where known + intentional/accidental/speculative/legacy complexity findings + Maintainability Risks / revisit triggers when material | review starts from important Workspace UCs/paths/pressure, not pattern inventory; a valid result is no architecture change justified | `architecture-state-review-workflow.md` | none |
| `UC-PLAN-ARCH-WORKSPACE-USES` | Discover / Review Workspace Use Cases | active proportional | `DIR-PLAN-ARCHITECTURE` | establish the architecture-relevant current-work picture from canonical Workspace UCs plus explicit candidate useful results without taking canonical UC lifecycle authority | explicit important-work picture is needed or current/future Workspace work has materially changed | important current canonical Workspace UCs + architecture-relevant candidate useful results/future UC candidates + relevance/frequency evidence when useful + canonical Workspace Planning handoff when establishment/change/topology is required | Architecture Planning consumes canonical UC identity from registries and may discover candidates, but does not itself canonically establish/change UC identity; frequency is evidence, not identity | `workspace-use-case-discovery-workflow.md` | none |
| `UC-PLAN-ARCH-PATH` | Trace / Evaluate Architecture-Relevant Path | active proportional | `DIR-PLAN-ARCHITECTURE` | understand what must actually be understood, changed or executed for one material result and expose architecture cost/pressure | one Workspace UC, important Workspace Change Case, Extension-derived future UC or Application Scenario needs path analysis | checked Workspace Understanding Path, Workspace Change Path or Runtime Realization Path + qualitative architecture findings | path analysis is evidence, not automatically a decision to refactor/abstract | `architecture-path-analysis-workflow.md` | none |
| `UC-PLAN-ARCH-PRESSURE` | Establish / Review Workspace Change Pressure | active proportional | `DIR-PLAN-ARCHITECTURE` | determine where important current/future work creates architecture pressure and which generalized Change Axes are evidence-backed | Workspace architecture must account for important UCs, Workspace Change Cases, Extensions, constraints or observed history | Change Pressure picture + evidence-backed Change Axes/confidence + Change Hot Paths + material architecture findings | Workspace Use-Case Discovery is an upstream capability whose output is consumed here; Change Axis is not a requirement to generalize and speculative futures do not pay architectural tax | `architecture-change-pressure-workflow.md` | none |
| `UC-PLAN-ARCH-DECISION` | Plan / Review One Material Architecture Decision | active proportional | `DIR-PLAN-ARCHITECTURE` | select/review one architecture choice by its correctness and effects on important current/future Workspace paths | one material architecture pressure/problem/choice is ready for explicit comparison | selected Architecture Decision + Intent + affected-path conclusion + Rejected Complexity + Revisit Trigger when useful | pattern/abstraction is a candidate answer, not the goal; decision must not optimize one future path while ignoring important ordinary UCs | `architecture-decision-workflow.md` | none |
| `UC-PLAN-ARCH-EVOLUTION` | Plan / Review Workspace Architecture Evolution | active proportional | `DIR-PLAN-ARCHITECTURE` | select a coherent target architecture change when several related decisions/risks must move together | current Architecture State and accumulated pressure require coordinated multi-decision evolution | selected target architecture/evolution direction + boundaries/transition constraints + routed downstream realization work | not detailed implementation task/Slice planning; later refactoring does not prove the earlier simpler architecture was wrong | `architecture-evolution-workflow.md` | none |
| `UC-PLAN-ARCH-DISCOVER-WEUC` | Discover Contextual Workspace Evolution Use Cases | active proportional | `DIR-PLAN-ARCHITECTURE` | discover bounded future Workspace-evolution work instances against a concrete current owner/change surface | explicit WEUC/evolvability discovery is requested or Architecture planning needs contextual future-change evidence for a sufficiently concrete area | contextual WEUC instances + expected Workspace Change Path + likelihood/value/timing evidence + friction/fan-out/risk + architecture-handoff yes/no | dedicated independently useful result; not a mandatory scan of every area; does not replace broad current/candidate Workspace-use discovery or canonically establish ordinary Workspace UCs | `workspace-evolution-use-case-discovery-workflow.md` | none |

`Architecture Flag`, `Architectural Tax`, `Architecture Intent`, `Change Pressure`, `Change Axis`, `Workspace Change Hot Path`, `Maintainability Risk`, `Revisit Trigger`, Workspace Work Paths and Runtime Realization Paths are concepts/techniques/results inside these capabilities, not separate Use Cases merely because they are addressable.
