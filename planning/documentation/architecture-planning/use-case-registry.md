| `UC-PLAN-ARCH-PRESSURE` | Establish / Review Workspace Change Pressure | active proportional | `DIR-PLAN-ARCHITECTURE` | determine where important current/future work creates architecture pressure and which generalized Change Axes are evidence-backed | Workspace architecture must account for important UCs, contextual WEUCs, Workspace Change Cases, Extensions, runtime constraints or observed history | Change Pressure picture + qualitative work-cost evidence + evidence-backed Change Axes/confidence + Change Hot Paths + material architecture findings | Workspace Use-Case/WEUC discovery is upstream evidence; Change Axis is not a requirement to generalize and speculative futures do not pay Architectural Tax | `architecture-change-pressure-workflow.md` | `оцени давление на архитектуру` |
| `UC-PLAN-ARCH-DECISION` | Plan / Review One Material Architecture Decision | active proportional | `DIR-PLAN-ARCHITECTURE` | select/review one architecture choice by correctness and explicit trade-offs across important Workspace work, contextual WEUCs and representative runtime paths | one material architecture pressure/problem/choice is ready for explicit comparison | selected Architecture Decision + Intent + affected Work-Cost/path conclusion + implementation-sequence recommendation when material + Rejected Complexity + Revisit Trigger when useful | pattern/abstraction is a candidate answer, not the goal; decision must not optimize one future path while ignoring ordinary UCs or redefine product priority | `architecture-decision-workflow.md` | `прими архитектурное решение` |
| `UC-PLAN-ARCH-EVOLUTION` | Plan / Review Workspace Architecture Evolution | active proportional | `DIR-PLAN-ARCHITECTURE` | select a coherent target architecture change when several related decisions/risks must move together under the same work-cost model | current Architecture State and accumulated pressure require coordinated multi-decision evolution | selected target architecture/evolution direction + work-cost trade-offs + boundaries/transition constraints + routed downstream realization work | not detailed implementation task/Slice planning; later refactoring does not prove the earlier simpler architecture was wrong | `architecture-evolution-workflow.md` | none |
| `UC-PLAN-ARCH-DISCOVER-WEUC` | Discover Contextual Workspace Evolution Use Cases | active proportional | `DIR-PLAN-ARCHITECTURE` | discover bounded future Workspace-evolution instances against a concrete current/target owner/change surface and assess when preparing now is justified | explicit WEUC/evolvability discovery is requested, Architecture planning needs contextual future-change evidence, or Application SDS Step 3 needs architecture-driving future-change evidence | contextual WEUC Types/instances + likelihood/horizon/value/confidence + current-work overlap + preparation-now/deferred cost + expected Change Paths + Work-Cost/friction/risk + architecture-handoff yes/no | dedicated independently useful result; not a mandatory scan; future likelihood alone does not justify architecture when preparation tax is high/deferral cheap | `workspace-evolution-use-case-discovery-workflow.md` | `собери WEUC` |

`Architecture Flag`, `Architectural Tax`, `Architecture Intent`, `Change Pressure`, `Change Axis`, `Workspace Change Hot Path`, `Maintainability Risk`, `Revisit Trigger`, Workspace Work Paths and Runtime Realization Paths are concepts/techniques/results inside these capabilities, not separate Use Cases merely because they are addressable.
