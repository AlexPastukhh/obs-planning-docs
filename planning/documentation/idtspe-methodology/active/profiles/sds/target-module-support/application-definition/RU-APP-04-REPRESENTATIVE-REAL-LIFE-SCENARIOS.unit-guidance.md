# Application Definition — Scenario / Evolution Coverage Guide

Status: active supporting guidance; **not** a semantic/schema owner. The filename is retained for compatibility with existing links.

Canonical Benefit and `RU-APP-04` coverage semantics are owned by [`TM-APPLICATION-DEFINITION`](../../target-modules/TM-APPLICATION-DEFINITION.md). Scenario journeys and Application Contributions belong to [`TM-SCENARIO-PLANNING`](../../target-modules/TM-SCENARIO-PLANNING.md); unrealized downstream bodies belong to [`TM-EVOLUTION-STEP`](../../target-modules/TM-EVOLUTION-STEP.md).

## Refinement questions

- Which accepted `AB-*` / material `BC-*` clauses have a current Scenario or planned Step-owned Scenario covering them?
- Which real-life path or Application Contribution is materially distinct and requires its own Scenario/family coverage decision?
- Which accepted intent remains uncovered, and is a concrete Step justified yet?
- Do coverage links point to the natural owners instead of copying a journey into Application Definition?

A Benefit can relate to several Scenarios, and one Scenario can manifest several Benefits. This guide does not require a Scenario per Benefit or a Step for every possible future idea.
