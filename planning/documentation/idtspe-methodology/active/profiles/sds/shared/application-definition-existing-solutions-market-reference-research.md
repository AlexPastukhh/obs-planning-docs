# Application Definition — Existing Solutions / Market / Reference Research

Status: active reusable Application Definition guidance  
Owner: `TM-APPLICATION-DEFINITION`

## Purpose

Before committing to a custom Application Concept, proportionally check whether the Need is already solved well enough and what can be learned from existing products.

The research serves decisions such as:

```text
use existing solution
buy
adapt/configure
integrate
extend
build custom
hybrid
```

It is not a mandatory competitor-report ceremony.

## Research Depth

### MINIMAL_REFERENCE_CHECK

Typical for personal tools, small experiments, one-off/internal utilities or deliberate build-for-learning projects.

Enough to answer:

```text
Is there an obvious existing solution?
Which references are worth learning from?
Am I knowingly building anyway?
```

### COMPARATIVE_SOLUTION_RESEARCH

Typical for serious internal/team applications or material build/maintenance cost.

Study:

```text
direct alternatives
manual/substitute workflows
adjacent products
important user feedback / limitations
interaction/reference patterns
integration/ownership constraints
```

### MARKET_AND_COMPETITOR_RESEARCH

Typical for external/commercial or otherwise serious long-lived products.

May additionally include:

```text
target segment
direct competitors
substitutes
adjacent references
expected/common capabilities
market gaps
pricing/business-model evidence — only when decision-relevant
distribution/platform constraints
user reviews/community feedback
switching/adoption constraints
```

No fixed competitor/reference count is required. Stop when evidence is sufficient for current Decisions.

## Existing-Solution Sufficiency Gate

Ask first:

```text
Does an existing solution satisfy
Need + constraints + ownership/privacy/integration expectations
well enough?
```

If yes:

```text
surface a Step-02 own-software-contribution challenge Finding Candidate
→ Core Finding Disposition selects Step-02 revalidation/reopen when warranted
→ consider use / buy / adapt / integrate / hybrid
→ custom Application Definition may terminate
```

## Reference Categories

```text
DIRECT ALTERNATIVE
SUBSTITUTE
ADJACENT REFERENCE

```

Reference products are Evidence and Idea generators, not semantic authority for our product.

## What To Extract

For each material reference:

```text
Need/result covered
important capabilities/flow
notable simplicity/convenience
friction
user value/complaints when evidenced
responsibility boundary
integration/data-ownership model
patterns worth borrowing
patterns worth avoiding
remaining gap relative to our Need
confidence/source
```

## Use In IDTSPE

