# Phase 03 — Application Definition — Generic

Status: active module-driven SDS phase

## Primary Target Module

```text
TM-APPLICATION-DEFINITION
```

One Application Definition Target owns together:
```text
Application Concept
Application Responsibility Boundary
proportional Existing-Solution / Market / Reference Research
proportional Realization Feasibility
```

`TM-PROTOTYPE` is conditional Evidence support when an unresolved concept/responsibility/feasibility Decision benefits from an experiment.

## Source Lineage

```text
Need / Desired Outcome
→ selected Step-02 real-world route/result
→ exact own-software contribution
→ TM-APPLICATION-DEFINITION
   may produce optional Refined Core Real-Life Scenario
→ Prototype / Scenario Discovery
```

## Revalidation

Later Scenario/Domain/current-implementation Evidence may challenge the same Application Definition. Core Finding Disposition may select revalidation/reopen; do not create a separate Realization-Stress Target by default.


## Existing Solutions / Reference Research

Before accepting a custom Application Concept, proportionally check:

```text
does an existing application already solve the Need well enough?
what direct alternatives/substitutes exist?
what adjacent products are useful references?
what should be borrowed or avoided?

for serious external/commercial products:
  what market/competitor/user/adoption evidence
  materially changes the concept?
```

Possible outcomes:

```text
continue custom build
adapt/configure existing
integrate existing
buy/use existing
hybrid
challenge Step 02 because custom software is no longer justified → Core Finding Disposition selects Step-02 revalidation/reopen when warranted
```

Reference/research observations surface Finding Candidates. Core Finding Disposition may resolve accepted material as Evidence, Idea or another appropriate State/lifecycle input. Reference products do not automatically define our Scenarios, Screens or Features.


## Core Real-Life Scenario Refinement

After existing-solution/reference research and Application Concept comparison, Application Definition may optionally produce a more detailed application-aware real-life route:

```text
Fundamental Need
+ actor/context
+ human/manual/external steps
+ Application contribution
+ real-world result
```

This is still not an Application Scenario.

If present, it becomes the nearest real-life Source for Prototype/Scenario Discovery.

If absent, the selected Step-02 route/result remains the Source.
