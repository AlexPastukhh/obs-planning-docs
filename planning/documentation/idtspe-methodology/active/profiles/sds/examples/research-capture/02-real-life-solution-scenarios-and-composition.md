
# Phase 02 — Real-Life Solution Discovery — Research Capture

Status: active worked example

## Sources

```text
Need:
  preserve useful research material
  without breaking the current reading/thinking flow

Desired Outcome:
  useful material remains available for later thinking/use

Current Reality:
  useful fragments are often lost,
  or preserving them creates too much interruption

Existing routes:
  bookmark
  copy into notes
  keep tab open
  read-later application

Constraints:
  low interruption
  preserve enough source context
```

## Dynamic Target Formation

This example does not assume one fixed solution-scenario Target Type.

It forms two material Targets because two independently useful real-life results need comparison.

### T-RC-01 — Preserve Material During Active Research

Purpose:

```text
select a real-life route for preserving useful material now
without breaking current work
```

Ideas:

```text
bookmark current page
copy selected text into notes
use existing read-later/highlight tool
use low-friction temporary capture
```

Selected route for the example:

```text
temporary low-friction capture
of selected material + source context
```

### T-RC-02 — Revisit Captured Material Later

Purpose:

```text
select what should happen to captured material
after the active research moment
```

Ideas:

```text
organize immediately during capture
leave it in permanent inbox
temporary holding → later review/triage
automatic classification
```

Selected route:

```text
temporary holding
→ later focused review/triage
```

## Topology

```text
T-RC-01 FLOW_TO T-RC-02
```

This relation says the real-life result from capture enters later review.

It does not automatically make T-RC-01 a Source for T-RC-02.

In this example T-RC-02 additionally depends on the accepted semantic result:

```text
captured material remains durably reviewable
```

so that accepted output is explicitly included in T-RC-02 Sources.

## Composition Decision

No separate composition Target is needed here.

The two accepted routes already combine mechanically:

```text
notice useful material
→ capture it quickly
→ continue current work
→ later review/triage
```

If the example instead had two materially different whole routes:

```text
A:
  capture → immediate organization

B:
  capture → temporary holding → later review
```

and selection between them remained unresolved after local Target decisions, then a normal dynamically formed composition Target would be justified.

## Own-Software Contribution Candidate

The accepted real-life route now supports this candidate:

```text

  + later review/triage support
```

This is still a Step-02 result, not the final Application Definition.
