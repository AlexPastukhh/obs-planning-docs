# UC-DOC-MAINTAIN-EXAMPLE — Maintain Documentation Example

## Situation

Reusable meaning would be materially easier to understand through demonstration, or an existing example is stale, misleading, too large, or incorrectly treated as authority.

## Result

A current non-authoritative example demonstrates the intended result/process/shape/behavior and is reachable from the semantic owner it illustrates.

## Process

1. Confirm that a concrete example adds understanding beyond the reusable rules themselves.
2. Keep a small example inline when a separate file adds no value.
3. Split a separate Example only when it becomes substantial or reusable.
4. Make the filename/header clearly identify what the example demonstrates.
5. Reference the semantic owner whose rules the example demonstrates.
6. Never define stable rules only in the example.
7. Update or retire the example when the demonstrated owner changes materially.
8. Ensure separate operational examples remain reachable from a current Use Case or a reachable semantic owner.
