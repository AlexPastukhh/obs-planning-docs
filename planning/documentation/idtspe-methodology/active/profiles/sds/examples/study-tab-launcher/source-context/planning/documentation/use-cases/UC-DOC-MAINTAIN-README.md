# UC-DOC-MAINTAIN-README — Maintain README Navigation

## Situation

An area's structure/responsibilities changed, readers cannot naturally determine what the area contains, or the README duplicates semantic bodies instead of serving structural navigation.

## Result

The README accurately maps the current area and direct-child responsibilities, with natural next navigation and without becoming a second owner of Use-Case/Process/Principles meaning.

## Process

1. Identify the current area's responsibility.
2. Identify the immediate child files/areas that readers need to understand.
3. Describe each direct child's responsibility briefly.
4. Link the natural next read when useful.
5. Keep detailed capability/process/term bodies in their semantic owners.
6. Do not create a separate Use Case for each README merely because that README exists.
7. Remove stale routes when an owner moves/retires.
8. Keep legacy/provenance routes explicit when staged migration requires them.
