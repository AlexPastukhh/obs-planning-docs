# Consumer / Source Integration

Reference Knowledge owns reusable Bank/Entry/Vocabulary/Landscape meaning. It does not grant consumer-side Source authority automatically.

```text
Bank Entry / Analysis / artifact locator
→ discovered by a consumer
→ consumer evaluates applicability/authority/coverage
→ consumer binds the accepted Source Subject through Core Source State
```

Bank existence, mounting, tagging, domain classification or prior analysis do not make an Entry authoritative for every consumer responsibility.

## Producer / Consumer Ownership

If an artifact is already owned by another Target/repository owner, keep that producer ownership. A Bank Entry may reference the artifact rather than copy it merely for discoverability.

A consumer may create local analysis/classification concerning a visible Entry without mutating the upstream Entry when Bank policy allows it.

## 2D Visual Production Compatibility

When a 2D Visual Production profile is active:

```text
Reference Knowledge Entry
→ candidate reusable visual material
→ 2D Visual Material Preparation / local visual-material registry when material
→ responsibility-relative qualification/coverage
→ downstream Core Source binding
```

Reference Knowledge does not replace:

- 2D visual-material qualification/preparation;
- responsibility-specific visual Source coverage;
- consumer role/authority/requiredness/freshness;
- production-owned prepared/derived material.

The 2D profile does not automatically provide decomposition/analysis Knowledge Basis for any future visual-domain Reference Knowledge pack. If such a pack is later derived, its analysis model must be derived independently under the Domain Pack model. Production methodology and reference analysis remain separate responsibilities.

## Retention Back To The Bank

Material discovered or produced during another Target may be retained in a Bank when reusable value and authority justify it. Retention creates/reuses Bank knowledge; rejected production output may still be a useful reference artifact.
