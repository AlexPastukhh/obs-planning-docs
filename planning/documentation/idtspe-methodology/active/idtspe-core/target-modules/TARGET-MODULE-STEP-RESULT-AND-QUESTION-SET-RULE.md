## Core Projection

```text
current task / scope / accepted Sources
→ actual material Target Resolution Requirements

Target Formation
→ required reusable-model check
→ applicable Target Module Model when one fits

Target Module Model
→ reusable recurring-scope/requirement-pattern recognition
→ complete prepared Module-defined Unit Definition inventory

concrete Target
→ Requirements remain grounded in current task/scope/Sources
→ prepared Units cover the responsibilities they actually fit
→ Core/contextual completion handles uncovered needs
```

A Target Module therefore packages reusable analysis/coverage; it does not semantically create a Requirement merely because a recurring pattern appears in the Model.

## Module-Defined Unit Inventory Projection

Applying a Target Module Model forms a Target Module Instance with the complete Module-defined Unit inventory required by the Meta-Model. Each reusable Unit Definition conforms to the canonical Target Work Unit contract; this projection does not restate Collection/Slot/simple-composite/runtime-set rules.

```text
selected Target Module Model
→ Target Module Instance
→ complete Module-defined Unit inventory
→ each Unit follows the canonical Target Work Unit contract
```

Every Module-defined Unit remains addressable in the Target according to the canonical Unit applicability/materiality/disposition contract. Materiality controls substantive Unit work/depth, not whether a declared Module Unit silently disappears.

## Requirement Coverage Projection

```text
recognized recurring requirement pattern
→ actual concrete Requirement grounded in current task/scope/Sources
→ prepared Unit responsibility when it fits
→ canonical Unit Resolution / Current Result Content
→ Requirement coverage when the Requirement completion criterion is actually satisfied
```

One Unit may cover several Requirements and one Requirement may require several Units/other owners. The concrete Target records `Covered By` explicitly only when the mapping would otherwise be ambiguous or materially reviewable.

## Questions / Drivers

Reusable questions remain guidance on the natural Requirement/Unit/Slot subject. Preset prompts do not automatically become Question State Units or USER-facing interview questions. There is no standalone `Target Question Set` semantic owner.

## Contextual Completion

A selected Target Module may cover only part of the concrete Target. Missing material needs remain visible and are completed through the canonical Target Formation flow: direct coverage where sufficient, applicable Core-defined Units, Contextual Slot only when the missing formal role remains inside one Unit responsibility, or Contextual Unit when a distinct bounded responsibility remains.

## Target Step Result Projection

Target Step Result composition is owned by `TWU.TARGET-STEP-RESULT`. The Target Module contributes the formed Target Module Instance/result family; applicable Core-defined and actually formed Contextual Unit contributions integrate through their canonical Result Destinations.
