# IDTSPE Always-On Proportional Work Model

Status: active generic work-model contract; compatibility path for former opt-in `idtspe.work`

## Core Rule

IDTSPE is already the default planning/resolution work model in this methodology environment. The USER does **not** choose whether to enable it.

```text
IDTSPE always active
→ Use Cases choose the smallest useful composition
→ Broad Discussion may be the whole current composition
→ deeper Target/State/Lens/Checkpoint structure appears only when useful
```

Canonical proportionality owner: [`shared/contextual-methodology-application-contract.md`](shared/contextual-methodology-application-contract.md).

## `idtspe.work` Compatibility Meaning

Existing command/helper phrase compatibility may remain:

```text
idtspe.work
работай через idtspe
```

It now means:

> explicitly refresh/reaffirm the current IDTSPE Use-Case-driven work composition and make relevant IDTSPE structure visible where useful.

It **does not enable** IDTSPE and does not change an off/on mode flag.

If Core governance is stale, the command may bootstrap/refresh it. Otherwise it simply routes through the current Use-Case Registry + `UC-IDTSPE-COMPOSE-CURRENT-WORK`.

## Normal Interpretation

```text
USER input
↓
Use-Case Registry applicability check
↓
UC-IDTSPE-COMPOSE-CURRENT-WORK
↓
Broad Discussion
  + only material explicit Core State
  + Target/Target Module only if bounded result helps
  + Lenses/Knowledge only if relevant
↓ when whole-state integration helps
UC-IDTSPE-INTEGRATE-CURRENT-WORK
↓
continue / revalidate / handoff / exact work
```

## Broad Discussion First, Not Broad Discussion Only

Broad Discussion may span many turns. Material logical parts may use Key Points; material candidate meaning may become a formal Proposal when addressability/review/lifecycle helps.

Do not force a visible 15-port form, full State dump, Target Result or Artifact Placement into every reply.

## Existing Artifacts First

When a logical Target/owner already exists, prefer `REFINE / EXTEND / REVALIDATE / REPAIR` over inventing a duplicate owner. Existing canonical owner artifacts become current Sources when they are actually authoritative/relevant.

## Profile Boundary

IDTSPE being always active does not mean SDS is always active.

```text
generic work
→ Core only

software/application planning where SDS semantics are relevant
→ Core + SDS profile components

future profile
→ Core + that profile
```

Profile selection is contextual composition, not an IDTSPE enablement switch.

## High-Level Example

```text
USER asks a conceptual planning question
→ IDTSPE already active
→ Compose UC selects Broad Discussion only
→ no Target/State/Lens/checkpoint created

later the question becomes an addressable implementation decision
→ same UC forms/reuses a Target
→ scans relevant TM/Lens/profile registries
→ only matched components are loaded
```
