# Review, Proposal Workup и Pre-Update — независимые примеры

Дата: 2026-09-24. Это объясняющие примеры, не дополнительная методология. Начните с текущего контракта нужного TM.

| Задача | Пример | Что показывает |
|---|---|---|
| Найти и разобрать Findings | [Реальный review](review-findings.example.md) | Два Units, наблюдение отдельно от исправления, доказательства Priority/RE, upstream/downstream, отдельные Core Proposals |
| Сравнить существенные Proposals | [Иллюстративный workup](proposal-workup.example.md) | Два варианта на заданной учебной базе, impact/QRPE, незакрытый USER selection |
| Согласовать конкретные операции до обновления | [Реальный Pre-Update](pre-update-plan.example.md) | Адресуемые пути, операции, preserve/check; явный omission |
| Проверить итог реального ремонта | [Проверка](verification.md) | Разделение исторической базы и текущего состояния |

Review и Pre-Update используют один реальный ремонт для удобства чтения. Между модулями нет обязательной последовательности. Workup — отдельная явно вымышленная ситуация: он не приписывает пользователю новый выбор. Для детерминированных исправлений review достаточно обычных Core Proposals.

[Полная копия документации Launcher](../../../profiles/sds/examples/study-tab-launcher/README.md) показывает несколько SDS owners на одном проекте. Все ссылки ведут внутрь этой методологии, не в живое приложение.
