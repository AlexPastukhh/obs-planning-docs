# UC-SESSION-CHECKPOINT — Integrate Current Session Checkpoint

## Situation

Broad Discussion and current work have accumulated enough material that accepted meaning, unresolved items, or the current plan/state are distributed or no longer reliably reconstructible from the latest messages alone.

## Result

A coherent current Checkpoint exists as Session State, with material current meaning integrated and useful unresolved/continuation points explicit.

## Process

1. Treat this Process as Checkpoint Integration: start from the existing Session State, if any.
2. Review material work accumulated since the previous Checkpoint or coherent state.
3. Integrate accepted/current meaning into the appropriate existing or new state units.
4. Preserve unresolved questions, decisions, risks/problems, or alternatives when they remain material.
5. Remove, supersede, or clearly mark stale/duplicated working representation when possible.
6. Restructure files/folders only when the current meaning benefits from a different representation.
7. Record useful continuation points when they are not obvious from the integrated state.
8. Treat the resulting Checkpoint as ordinary Session State that may later be persisted, handed off, or refined.

Shared meaning: [`../principles-and-terminology.md`](../principles-and-terminology.md)

A Checkpoint has no mandatory template and does not require the full conversation transcript to be stored.
