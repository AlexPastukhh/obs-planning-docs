  "text": "## Finding Model\n\nКлассифицируй существенные содержательные находки по четырём типам. **Question не является отдельным Finding Type**: вопросы могут относиться к любому finding.\n\n### Problem — `F-P-*`\n\nПодтверждённое текущее отклонение: существующее состояние уже нарушает применимую цель, Need, FR, Work Requirement, constraint, Scenario или ожидаемое поведение.\n\nНе называй Problem то, что подтверждено только как возможность будущего сбоя.\n\n### Risk — `F-R-*`\n\nПравдоподобный механизм будущей проблемы, которая ещё не подтверждена как фактически проявившаяся в рассматриваемом состоянии.\n\n### Decision Uncertainty — `F-U-*`\n\nСущественная развилка решения/интерпретации: существуют разные жизнеспособные варианты с материально различающимися последствиями, а безопасный выбор пока не установлен. Это не просто «чего-то не знаем».\n\n### Improvement Opportunity — `F-O-*`\n\nТекущее решение уже способно удовлетворить применимую цель/requirement, но есть способ сделать путь существенно проще, дешевле, быстрее, надёжнее, понятнее, менее затратным или лучше сохранить option value. Не повышай Opportunity до Problem без нарушения требования.\n\n### Evidence Gap / Review Limitation\n\nНедостаток доказательств или невозможность независимо проверить аспект — не пятый Finding Type. Фиксируй отдельно как `Evidence Gap / Review Limitation`: что не подтверждено, почему и какие утверждения из-за этого ограничены. При наличии конкретного потенциального негативного механизма дополнительно может существовать Risk.\n\n### Location / Relative Level\n\nДля finding указывай, когда это существенно:\n- semantic target: `Need / FR / Scenario / SRU (с parent path) / implementation / execution / other`;\n- relative level к текущей работе: `CURRENT / UPSTREAM`.\n\nUpstream означает, что finding относится к уже принятому/спланированному родительскому уровню и способен изменить downstream работу. Чем выше upstream finding и чем больше downstream он способен обесценить, тем выше приоритет его явного рассмотрения.\n\n### Disposition\n\n`Deferred` — не отдельный Finding Type. Используй disposition, например: `act-now / deferred / resolved / mitigated / invalidated / accepted / no-action / superseded / reopened`.\n\nДля deferred укажи причину, revisit trigger и возможное последствие после наступления trigger.\n\n### Questions / Proposals\n\nУ finding могут быть вопросы, User Assistance и один или несколько Proposals.
