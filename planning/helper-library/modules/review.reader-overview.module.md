  "text": "## Review Reader Overview — результат для пользователя и карта отчёта\n\nЭто **представление проверенных canonical Findings/Proposals**, не новое review, taxonomy, шкала приоритета или источник истины. Пользователь должен быстро понять итог, важные решения и где читать доказательства.\n\n### Начало ответа\n\n1. **Вердикт (обычно 1–3 предложения):** что проверено, насколько полно, есть ли подтверждённые существенные Problems, значимые Risks/Decision Uncertainties/Opportunities и каковы последствия. «Не найдено существенных Problems» ≠ «замечаний нет». Главное ограничение проверки назови сразу. Не выдавай неподтверждённое за подтверждённое, не придумывай счётчики и статусы.\n2. **Приоритет внимания:** `CRITICAL`, затем `HIGH User Review Priority` вне зависимости от Finding Type и `act-now/deferred`. Каждую важную находку представляй понятным названием и конкретной ситуацией **до** ID: `суть → тип → последствия → связанный PR и trade-off → Decision Autonomy / нужен ли выбор → следующий шаг`. ID нужны для перехода к canonical записи, а не вместо объяснения. Finding не подменяй описанием исправления.\n3. **Тип явно:** `Проблема (F-P)` — доказанное нарушение; `Риск (F-R)` — возможное будущее событие; `Неопределённость решения (F-U)` — значимая развилка; `Возможность улучшения (F-O)` — допустимый путь с альтернативой. Для meta-review соответствующие `MR-F-*`. Если исходный ID общий (`F-01`), сохраняй его и бери Type из canonical записи, не угадывай по номеру. Если Type отсутствует или не установлен, честно пометь это, а не присваивай тип по предположению. `Evidence Gap` не пятый Finding Type.\n\nРядом с важным Finding покажи `PR-ID`, **конкретное предлагаемое изменение**, статус и действие. При множестве HIGH/CRITICAL сначала выдели 2–4 главных, остальные сгруппируй по смыслу/типу, **не теряя отдельных необходимых решений и ID**. `HIGH` — важность рассмотрения, не автоматическая срочность реализации; `deferred` допустим с revisit trigger. Если высоких нет — сообщи коротко. Различай `pending`, `selected candidate`, `committed` и подтверждённую запись: кандидат не является commit. В meta-review отделяй source references от новых Findings.\n\n### Карта полного отчёта\n\nПосле обзора дай короткий раздел «Что в полном отчёте»: обычно 3–6 **реальных** важных разделов с содержательным выводом и причиной открыть каждый. По необходимости включи baseline, WR/EA, Findings/Proposals, upstream/blocking, limitations, Candidate Composition. Если файл существует, опирайся на его фактические заголовки либо явно сопоставимые названия; не выдумывай страницы, якоря, пустые разделы или доказательства. Не дублируй первый экран.\n\nЗаверши «Что дальше / какие разделы стоит открыть»: требуемые решения и исправления, допустимое отложенное, место доказательств. Не заставляй читать файл целиком. Если полного отчёта нет, не описывай выдуманные разделы: дай карту реально имеющегося содержания и ограничение.\n\n### Чат, файл и согласованность\n\n- **В чате** покажи вердикт, важные Findings/Proposals и карту **до** ссылки. Не заменяй ответ одним именем файла. Только после подтверждённой записи дай прямую действующую ссылку (проверенная GitHub-ссылка допустима); не выдумывай URL и не требуй блока с именем файла.\n- **В создаваемом полном отчёте** после заголовка и нужных метаданных помести короткое «Краткий результат / Для пользователя»: вердикт, HIGH/CRITICAL, карта разделов, следующие шаги. Далее — полные canonical записи, доказательства, типы, альтернативы, dispositions и Review Log. Этот модуль сам по себе **не требует** создавать отдельный файл.\n- Обзор чата и файла должны совпадать по ID, типам, уверенности, статусам, PR и ограничениям. Если Finding/Proposal изменён, обнови оба резюме. Не создавай параллельные canonical записи; не утверждай сохранение без подтверждения.\n\nОбзор должен быть **коротким и информативным** (часто ~120–250 слов, при множестве значимых решений больше). Для тривиального review достаточно вердикта, замечания и следующего шага; не делай второй полный отчёт вместо обзора.\n\n[[module:output.situational-github-artifacts]]",
