Target Review / Underlying Context\n\nОпредели конкретное review, его target/version/scope, исходную задачу и доступный review-prompt/protocol. Не проверяй другой более новый review только из-за свежести.\n\n## 2. Review Identity / Lineage\n\nСохраняй IDs сущностей проверяемого review неизменными как source references. Новые findings самого meta-review не смешивай с ними: используй `MR-F-P/MR-F-R/MR-F-U/MR-F-O`, а новые Proposals meta-review — `MR-PR-*`. Явно показывай, какая запись принадлежит исходному review, а какая возникла только при meta-review.\n\n## 3. Independent Verification\n\nНезависимо проверь ключевые утверждения review и исходный объект в достаточной степени, чтобы оценить false positives, false negatives и severity. Не доверяй review только потому, что оно выглядит подробным.\n\n## 4. Review Protocol Compliance\n\nВосстанови обязательные требования к проверяемому review из исходного review-prompt, пользовательских указаний и контекста. Проверяй не только качество присутствующих элементов, но и отсутствие обязательных.\n\nЕсли protocol требовал finding classification, concrete reproduction, WR/EA statuses, Review Log, proposals, User Review Priority/Decision Autonomy, blocking status, limitations или другое — проверь содержательное выполнение. Если исходный protocol недоступен, не угадывай: укажи, что нельзя надёжно проверить.\n\n## 5. Finding Classification / Explanation\n\nДля каждого существенного утверждения review проверь:\n- не названа ли Risk подтверждённой Problem;\n- не названа ли Opportunity defect;\n- не превращён ли Evidence Gap автоматически в Risk/Problem;\n- действительно ли Decision Uncertainty содержит материально разные варианты;\n- показана ли конкретная ситуация/reproduction там, где это применимо;\n- связана ли Problem с целью/requirement и expected behavior;\n- для material questions/decision forks указан ли корректный `blocking / non-blocking / partially blocking` и affected scope.\n\n## 6. Level / Upstream / Scenario Impact\n\nПроверь, правильно ли review определило semantic target и CURRENT/UPSTREAM. Ищи пропущенные upstream findings, способные изменить parent SRU, Scenario, Need/FR, scope, costs, maintainability, accumulated complexity или staged/full strategy.\n\nОтдельно проверь, не было ли локальное исправление предложено там, где сначала требовалось пересмотреть upstream decision.\n\n## 7. User Review Priority / Decision Autonomy\n\nПроверь обе оценки независимо. Высокий impact не равен автоматически отсутствию технической компетентности ИИ, а низкий impact не даёт автономии при неизвестном пользовательском preference. Убедись, что как минимум оценены Need, scope, radical complexity/cost, Scenario/process impact, reversibility, evidence и AI competence.\n\n## 8. Work Requirements / Error Axes\n\nЕсли review работало с baseline, проверь корректность WR statuses, EA interpretation и новых findings. `EA` не должна трактоваться как подтверждённый defect только из-за наличия в baseline.\n\n## 9. False Positives / False Negatives / Severity\n\nСоставь:\n- подтверждённые замечания review;\n- ошибочные/слишком сильные замечания;\n- пропущенные Problems/Risks/Uncertainties/Opportunities;\n- неверную severity/impact оценку;\n- Evidence Gaps review.\n\n## 10. Proposal / Composition Review\n\nПроверь, отделены ли findings от remediation Proposals; не был ли user-origin Proposal ошибочно повышен до Requirement; представлены ли реальные alternatives; корректны ли `REQUIRES/CONFLICTS/...`; не был ли отдельный selected Proposal выдан за committed composition.\n\nЕсли meta-review предлагает изменение, оно само является `MR-PR-*`, а не автоматически принятой правкой. При нескольких взаимозависимых вариантах собери Recommended Remediation Candidate Composition вместо списка независимых рекомендаций.\n\n## 11. User Assistance / Review Records\n\nПроверь, не пропустило ли review минимально полезный пользовательский input и не делегировало ли лишнее. Если Review Log был обязателен, проверь его полноту, canonical IDs, dispositions, limitations и правдивость заявления о persistence.\n\n## 12. Meta-review Output\n\nВыведи:\n1. overall assessment review;\n2. подтверждённые findings review;\n3. false positives / overclaims;\n4. false negatives / omissions;\n5. protocol-compliance omissions;\n6. classification/explanation errors;\n7. level/upstream/Scenario-impact errors;\n8. User Review Priority / Decision Autonomy errors;\n9. Proposal/composition errors;\n10. Review Log / User Assistance errors;\n11. новые meta-review findings и связанные `MR-PR-*`;\n12. Recommended Remediation Candidate Composition, если применимо.\n\nНе исправляй проверяемый underlying object молча; meta-review оценивает review и формирует Proposals для дальнейшей работы.",
