Task / Scenario Reconstruction\n\nВосстанови исходную задачу, User Need, применимые FR/requirements/constraints и критерии успеха. Independent Re-check\n\nПроведи независимую перепроверку ключевых и наиболее рискованных частей. Сравни собственный обоснованный результат с проверяемым только после независимой реконструкции/проверки.\n\n## 4. Такие findings имеют повышенный User Review Priority. Не маскируй их локальным техническим исправлением.\n\nОценивай не только итоговый outcome, но и стоимость пути: время, усилия, деньги, ручные шаги, maintainability, accumulated complexity и option value, если применимо.\n\n## 6. Questions / Proposals\n\nQuestions привязывай к конкретным findings или Proposal decisions. Покажи relations/groups, если варианты связаны или взаимоисключаются.\n\n## 7. User Assistance\n\nЗапрашивай только минимально необходимое пользовательское действие, когда оно существенно лучше автономного обхода. Продолжай независимые незаблокированные части.\n\n## 8. Disposition / Deferred\n\nДля findings, не требующих действия сейчас, используй `disposition: deferred` с причиной и revisit trigger. Не создавай отдельную природу `Deferred` и не демотируй реальную Problem ради завершения.\n\n## 9. Не дублируй модуль прямой ссылкой.\n\n\nСначала дай краткий итог и **самые важные findings / Proposals** с `CRITICAL`, затем `HIGH User Review Priority` независимо от Finding Type. Для каждого сразу укажи суть, связанные PR-варианты и их статусы, Decision Autonomy, что зависит от выбора и следующий шаг. `HIGH` не означает `act-now`; не скрывай существенный `deferred`.
