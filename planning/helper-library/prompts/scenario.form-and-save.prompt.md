  "text": "Сформируй и сохрани Candidate Scenario для указанной мной цели, задачи или однозначно определяемого контекста.\n\nНе переходи глубже в реализацию, чем необходимо для корректного формирования Desired Scenario и его top-level Scenario Realization Composition.\n\n[[module:core.context-interpretation]]\n[[module:core.need-proposal-semantics]]\n[[module:core.scenario-realization]]\n[[module:core.proposal-composition]]\n[[module:core.decision-governance]]\n[[module:output.situational-github-artifacts]]\n\n\n## 1. Need / Goal\n\nВосстанови User Need / Goal и применимые Fundamental Requirements. Не превращай предложенный пользователем способ решения в Requirement только потому, что его предложил пользователь.\n\nЕсли Need / FR только выводятся из контекста, сохрани их candidate / inferred status.\n\n## 2. Desired Scenario\n\nОпиши желаемую реальность: существенный контекст, prerequisites, inputs, осмысленный путь/переходы, промежуточные состояния только если они важны, observable outcome и критерий того, что Scenario действительно удовлетворяет Need.\n\nScenario должен описывать желаемую реальность и путь к результату, а не внутреннюю реализацию. Сам Scenario не делай рекурсивным.\n\n## 3. Scenario Efficiency\n\nПроверь, что Scenario является достаточно простым и эффективным способом получить требуемый outcome.\n\nОсобенно проверь:\n- нет ли лишних шагов и необоснованно дорогих prerequisites;\n- нет ли существенно более простого пути к той же пользовательской ценности;\n- не создаётся ли лишняя нагрузка, время ожидания, ручная работа или иная стоимость процесса;\n- не предполагается ли полная сложная версия там, где разумнее validation-first / MVP / staged путь.\n\nЕсли существует существенно другой жизнеспособный Scenario, не подменяй им исходный молча: оформи его как отдельный Proposal / alternative Scenario.\n\n## 4. Scenario Realization Composition\n\nСформируй top-level Scenario Realization Units (SRU), совокупность которых обеспечивает существенные части и переходы Scenario.\n\nДля каждой material SRU укажи, где применимо:\n- SRU ID;\n- Purpose / contribution to Scenario;\n- Preconditions;\n- Inputs;\n- Required capability / behavior / state transition;\n- Outputs / resulting state;\n- downstream use;\n- Success Criteria.\n\nНа этом шаге не раскладывай SRU рекурсивно глубже без необходимости. Рекурсивная декомпозиция относится к последующему планированию реализации конкретной SRU.\n\n## 5. Alternatives / Proposals\n\nЕсли существуют несколько существенно разных разумных Scenario, SRU-compositions или решений, сохрани несколько Proposals. Не создавай альтернативы ради количества.\n\nДля material вариантов покажи влияние на Desired Scenario, scope, время, усилия, деньги/resources, maintainability/accumulated complexity если применимо, возможность staged realization, User Review Priority и Decision Autonomy.\n\n## 6. Candidate Scenario State\n\nСобери Recommended Candidate Scenario и соответствующую Scenario Realization Composition.\n\nПроверь:\n- покрывает ли Scenario Need / FR;\n- покрывают ли top-level SRU существенные части/переходы Scenario;\n- нет ли gaps или лишних SRU;\n- не спрятано ли implementation decision внутрь Scenario;\n- не добавлена ли преждевременная сложность;\n- нет ли unresolved решения, которое material меняет Scenario.\n\nНе называй Candidate Scenario committed до явного commit.\n\n## 7. Save\n\nСохрани Candidate Scenario как отдельное рабочее состояние, если доступно подтверждаемое рабочее или постоянное хранилище.\n\nСохраняй как минимум:\n- Scenario ID;\n- version;\n- status: `candidate / committed`;\n- Need / FR references;\n- Desired Scenario;\n- top-level Scenario Realization Composition;\n- SRU IDs;\n- существенные alternative Proposals;\n- unresolved decisions;\n- provenance/version metadata, если система это поддерживает.\n\n**Сохранение candidate state не является commit.**\n\nСчитай Scenario сохранённым только если фактически выполнена операция записи и её успешность можно разумно подтвердить. Если запись невозможна или не подтверждена, не утверждай, что Scenario сохранён: выведи отдельный блок `SCENARIO STATE — READY TO SAVE` с полным состоянием для последующего сохранения.\n\n## 8. Output\n\nКратко покажи:\n1. Need / Goal;\n2. Fundamental Requirements;\n3. Candidate Scenario;\n4. top-level SRU Composition;\n5. существенные alternatives / Proposals;\n6. unresolved decisions;\n7. User Review Priority / Decision Autonomy material решений;\n8. Scenario status;\n9. save status и место сохранения, только если оно действительно известно.",
